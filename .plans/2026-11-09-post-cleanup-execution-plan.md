# Execution plan after the companion/window cleanup

November 9, 2026. Reviewed after merging upstream `main` through `6d7d26d` into this research branch (`cdd38a5`). Upstream's default branch is `main`, rather than `master`. This updates implementation ordering; it does not claim another physical test. The [physical results](2026-11-09-surface-live-results.md) retain their original tested revision and limits.

**Start implementation on the existing owners. The later user-requested [transport-first foundation](2026-11-10-transport-first-rollout.md) centralizes core connections before new previews; no replacement window/session architecture is needed.** The cleanup supplies the shared native client, per-window state and naming operations we wanted. The worker-delivery experiment proposed below was completed on November 10 for an explicitly owned Codex runtime and real terminal TUI. [Results and limitations](2026-11-10-worker-delivery-results.md). Further streaming checks mostly belong with the production integration and supported-feature qualification.

**November 10 rollout update:** adopt the user's [preview-first sequence](2026-11-10-preview-first-rollout.md): quick isolated peer-link/LAN comparison ([completed](2026-11-10-peer-link-live-results.md)) → [shared transport/availability foundation](2026-11-10-transport-first-rollout.md) → manual stream previews → small terminal preview MCP with native Codex CUA → lifecycle/recovery qualification → background Chrome → Pi. Codex calling a preview tool does not require external structured delivery into Codex, so the worker adapter moves to the Pi phase. Enough feasibility work has run to start implementation; the remaining gates qualify the production slices.

`CompanionClient` is a **Vision-side client**, not a service Pi imports into the Mac. Pi calls Mac domain handlers; the headset client reaches those handlers through the paired protocol. The client does not own Mac processes, media production, coding-agent state or reasoning. Existing terminal WebSockets, preview WebView networking and bulk stream transport retain their separate jobs.

Route identity is not authentication. The new Keychain host identity and trusted-origin bindings should be reused, not bypassed by accepting a model/discovery-provided endpoint with a matching host ID. Media still needs its temporary, exact-target grant and transport trust; sharing the control client does not automatically secure an unrelated media listener.

## What was adapted in this merge

The three conflicts were in `WindowGateway.swift`, its tests and the native test runner. The optional probe now polls/resolves through typed `CompanionClient` methods. Receiver status lives in the existing window state record; probe command receipts remain bounded experiment state. It no longer retains the removed `CompanionAPI`, endpoint map or parallel window-presence map. Both upstream and probe checks were retained.

A new regression drives a real probe poll through the injected HTTP exchange, checks its body/status reporting, then replaces the accepted route while a poll is delayed. The old batch is rejected even when the accepted address is unchanged. Existing explicit-close, duplicate, late-resolution, restoration and no-extra-session checks still pass. This is automated integration evidence, not a rerun on the headset.

## Worker-delivery experiment: completed for an owned Codex runtime

**Completed follow-up:** native delivery/queue/steer, reconnect, permission wait and interruption were demonstrated. The adapter must reconcile uncertain requests because native queue IDs do not deduplicate, distinguish queue clearing from interruption, and track worker lifetime independently of the TUI. Keep the queue in Codex. The original experiment outline follows for reproducibility; it is no longer a prerequisite research task.

**Use one disposable, real terminal Codex session and submit to that same live agent through a small external adapter.** This can run on the Mac without the Vision Pro. Keep its normal harness/authentication and terminal UI. The independent Pi and `codex exec` fixture runs proved tool usability; they did not prove attachment to an existing interactive session.

1. Establish the exact SlopZooka session, native agent identity and runtime incarnation. Deliver a bounded idle task and correlate native acceptance with an independent effect.
2. Keep that agent busy. Submit an ordinary queued task; then explicitly steer the current turn. Verify queue versus execution and whether steering is actually supported. Measure a short navigation/verification request while busy: this informs whether Pi needs a narrow direct-navigation exception.
3. Interrupt, exercise a permission/user-input wait, exit the agent into its shell, and lose a delivery reply. Reconcile outcomes before retrying; never type a task into the shell or silently start a replacement agent. Verify Stop does not rely on the model responding.

The decisive result is a supported same-session submission/status path, with honest capability limits. If the existing TUI cannot be attached/steered reliably, choose an owned launch/attachment adapter or limit the exposed delivery modes. That is a real implementation decision; recreating a durable queue in Pi or driving the desktop composer would conceal it. No new native conversation UI is required to learn this.

Generic native Mac control remains a separate conditional shipping gate: runtime packaging/support, clean permission attribution and helper/update recovery must be qualified before offering arbitrary Mac apps. It need not block the already-demonstrated simulator/browser paths. The hosted native CUA initialization failure in the physical slot remains evidence of that distinction.

## Revised execution sequence

| Step | Small deliverable | Acceptance that matters |
| --- | --- | --- |
| 1. Integrate manual stream previews | Extend the existing frontend owner/resolver and Preview content. Start with selected Mac/Simulator windows using the exercised native H.264 path; preserve web previews. Companion-derived geometry drives native preview sizing, including phone aspect/rotation; the agent supplies no dimensions. | Works without a model, uses exact target identity and undistorted source aspect ratio, respects user scale/restoration, and reports fresh/unavailable state honestly. Rotation updates geometry; encoder downsampling does not resize the window. Extend Swift/TypeScript fixtures together and qualify the signed capture owner's permissions. |
| 2. Add the terminal preview MCP | Small list/open/close/rename wrapper over those same handlers, scoped to its terminal/workspace and paired client. Codex keeps its existing shell/native CUA. | Real interactive SlopZooka Codex controls the same visibly marked target it presents. No duplicate opens or app launch hidden in sharing. The actual native runtime/configuration is qualified; close sharing does not claim to cancel raw CUA input. |
| 3. Harden sharing and recovery | Provider owns viewer subscriptions independently of MCP connections, agent turns and app processes. Exercise retry, source replacement, permission/lock state, viewer stalls and reconnect. | Agent exit/Stop or one viewer closing leaves other viewing intact. Last viewer release may pause capture, not quit the source. Old actions/resolutions are rejected; ordinary-use text/motion and bounded recovery pass. |
| 4. Add background Chrome | Bring the tested owned browser provider into the same preview flow, with exact page identity and separate viewing/input lifetimes. | Two real terminals control two background tabs without stealing human typing; matching frames, navigation/resize, detach/recovery and stale-target rejection pass. |
| 5. Add Pi and structured worker delivery | Pi calls existing handlers; integrate the already-qualified worker adapter when Pi needs queue/steer/status/Stop. Capture context before menu focus changes. | One request reaches the correct worker/source and matching preview. Reconcile uncertain native submissions; resetting Pi does not own resource teardown. Keep or retire the thin preview MCP based on real usage, without moving domain ownership into Pi. |
| 6. Expand workspace preparation and voice/wrist entry | Model-led project setup, workspace naming and the selected voice entry use the same existing owners. | Real Poncho2 launch with partial-failure retry, useful protected names, explicit queue/steer/Stop and supported recovery. |

The worker adapter is no longer the first implementation prerequisite. Manual UI and preview MCP share handlers, so the MCP can follow as soon as the manual path works. No new window family, durable global coordinator, universal action language, Chromium embedder or model-specific media channel is needed for this sequence. See the preview-first plan for the exact first-slice acceptance and native-CUA boundaries.

Keep the first command path on existing authenticated request/snapshot machinery. The probe currently polls in the session-refresh path; that proves a connection, not a low-latency SLA. Production presentation delivery must avoid blocking ordinary refresh during a stalled optional command request. If polling is too slow, extend `CompanionClient` with bounded long-poll/push delivery. **Immediate Stop and any future direct pointer/keyboard input must not wait for periodic polling or model inference.** Bulk frames bypass both the control queue and the model.

## Remaining tests, by the decision they answer

The [Codex thread-handoff investigation](2026-11-10-codex-thread-handoff.md) additionally establishes native catalog access on the existing shared server, including this active conversation. **User-confirmed P2:** add a dedicated thread-list tab or section in the launcher, with **Continue Codex thread** through the same worker/session adapter. Codex supplies history/catalog/resume; the incremental work is primarily the list/filter UI and selection-to-session binding once the adapter exists. Preserve the native thread and original cwd; attach to a known live runtime or explicitly resume saved history. Prefer a compatible existing shared runtime when available, while retaining the tested owned-runtime arrangement. Shared history alone does not establish safe live adoption. No additional conversation database or window owner is needed, and this feature does not block the initial rollout.
